## Tools

- `recommender.py` `generate_report()` — the source of truth now; width- and depth-aware, zone-prioritized,
  factors in neighborhood-wide type variety and per-owner LU/SU balance. Regenerate any time cached
  data refreshes.
- `structure_fitter.py` — per-property / per-structure lookup CLI. Fixed 2026-07-23: both the
  `--property` report and `--structure` search modes were calling `structures_that_fit()` with area only,
  ignoring width/depth entirely. Now enforces both.
  ```
  python3 structure_fitter.py --property "75 JEFFERSON AVE"
  python3 structure_fitter.py --structure "DMV"
  ```
- `dongan_hills_zone_map.py` — interactive HTML zone map (uses the same width-aware engine via
  `best_service_for_zone`).
- **Upland Playground** (ugc.upland.me) — always verify fit in-game before committing Spark. UP2/width
  estimates come from MapPLUTO parcel polygons, not the game's internal grid, and can still be off.

## Key Caveats

1. **UP2 and width values are computed from MapPLUTO polygons**, not the game's internal UP grid. Two
   real-build misses so far — a Day Care on a too-narrow lot, and this session's Large Assisted Living
   recommendation (both from before per-property width checking was wired up everywhere) — always confirm
   in the Playground first, especially for anything near a size/width threshold, even now that width is enforced.
2. **Structure min sizes are from community research**, not official Upland docs.
3. **Multi-structure properties**: demolishing may remove every structure on that property, not just one.
4. **Zone-based category priority** (e.g. Zone 4/Buel Ave prioritizes "public" category first) can pick a
   very low-SU structure (e.g. Information Kiosk, 0.55 SU) over a higher-SU structure in a different
   category that would also fit (e.g. Barn & Nobles, 4 SU essential) — this is a deliberate zone-variety
   design choice in `auto_recommend()`, not a bug, but worth a manual look on any "BUILD Information Kiosk"
   row where a bigger essential/entertainment SU number was mentioned elsewhere for the same lot.
5. **Spark Hours** are the real bottleneck — prioritize the highest SU-per-SparkHour ratio structures first.
